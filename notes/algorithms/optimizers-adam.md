# 优化器：Adam / AdamW 与显存账

> 训练/并行类 · 小模块（枝干） · 挂靠：主线 A 枝干 A1 第 1 段（FP8 训练 → 优化器 → ZeRO/FSDP） · 挂载点：主线 A 第 6 步 serving 之后 · 必学，不推迟

---

## 解决了什么问题

训练一个模型，"往哪个方向走、走多远"由优化器决定。朴素 SGD 有几个硬伤：

1. **方向震荡**：只依赖当前梯度，梯度噪声大，路径来回摆动
2. **每参数同一步长**：不同参数尺度差异大（有的接近 0，有的很大），统一学习率顾此失彼
3. **稀疏特征吃亏**：低频参数更新太少，永远学不到位
4. **显存贵**：Adam 需要为每个参数额外存两个状态，大模型训练一半显存花在优化器状态上

Adam 解决 1-3（自适应 + 动量），AdamW 修正 4 里的一个细节（weight decay 耦合问题）。分布式训练时，优化器状态怎么切（ZeRO-1 / FSDP）是另一个高频考点。

## 核心思路

### 1. SGD 基线：为什么不够

```text
θ = θ - lr × g
```

- g 是当前梯度，lr 是学习率
- 问题：只看见"现在"，没看见"历史"；震荡时没有阻尼；每个参数都被同一个 lr 推

### 2. Adam：两个 EMA + 偏差修正

Adam 给每个参数维护两个指数滑动平均（EMA）：

```text
m = β1·m + (1-β1)·g          # 一阶矩：梯度的动量（方向感）
v = β2·v + (1-β2)·g²         # 二阶矩：梯度平方的 EMA（尺度感）

偏差修正（前几步 m/v 从 0 起步，会严重低估真实均值）：
m̂ = m / (1 - β1^t)
v̂ = v / (1 - β2^t)

更新：
θ = θ - lr × m̂ / (√v̂ + ε)
```

逐项理解：

| 项 | 作用 | 直觉 |
|---|---|---|
| m | 动量 | 梯度方向的历史平均，震荡互相抵消 |
| v | 自适应步长 | 梯度大的方向步子变小，梯度小的方向步子变大 |
| 偏差修正 | 前几步校准 | m/v 初始为 0，不修会偏小 |
| ε | 数值稳定 | 防止 √v̂ = 0 时除零 |

默认值：β1=0.9、β2=0.999、ε=1e-8。β2 接近 1 意味着 v 对历史非常保守——它用很长的窗口估计梯度方差。

### 3. 手算两步（验证理解）

设 β1=0.9、β2=0.999、lr=0.001，参数 θ 初始 1.0，梯度 g₁=0.1、g₂=-0.2：

```text
第 1 步 (t=1):
  m = 0.9×0 + 0.1×0.1 = 0.01
  v = 0.999×0 + 0.001×0.01 = 0.00001
  m̂ = 0.01 / (1-0.9) = 0.1
  v̂ = 0.00001 / (1-0.999) = 0.01
  θ = 1.0 - 0.001 × 0.1 / (√0.01 + 1e-8) ≈ 1.0 - 0.001 = 0.999

第 2 步 (t=2), g=-0.2:
  m = 0.9×0.01 + 0.1×(-0.2) = -0.011
  v = 0.999×0.00001 + 0.001×0.04 = 0.00004999
  m̂ = -0.011 / (1-0.81) ≈ -0.0579
  v̂ = 0.00004999 / (1-0.998001) ≈ 0.025
  θ = 0.999 - 0.001 × (-0.0579) / (√0.025 + ε) ≈ 0.999 + 0.000366 = 0.999366
```

要点：梯度从 +0.1 翻到 -0.2，但更新量没有翻倍——动量抵消了方向突变，二阶矩让"这次波动大"的方向步长变小。这就是 Adam"稳"的来源。

### 4. AdamW：解耦 weight decay

经典 Adam + L2 正则有个隐蔽问题：

```text
L2 正则：把 λθ 加进梯度 → g' = g + λθ
但 Adam 会用 v̂ 归一化 g' → weight decay 的实际强度被梯度尺度扭曲了
```

AdamW 的修法：**weight decay 不进入梯度，直接在更新后减**：

```text
θ = θ - lr × m̂/(√v̂ + ε) - lr × λ × θ
    └────── 梯度部分（Adam 原样）────┘   └─ 权重衰减（独立于梯度）─┘
```

- 效果：衰减强度稳定，不随梯度大小波动
- 现状：主流训练（LLaMA/Qwen/DeepSeek 系）默认 AdamW；面试问"AdamW 和 Adam+L2 区别"要能说清这一点

### 5. 显存账（训练必考）

每个参数在训练中占多少字节：

```text
全精度（fp32 训练）:
  参数 θ     4 B
  梯度 g     4 B
  动量 m     4 B
  二阶矩 v   4 B
  ──────────────
  合计      16 B / 参数

主流混合精度（fp16/bf16 训练）:
  fp16 参数   2 B   （前向/反向用它）
  fp32 master 4 B   （优化器只更新 master）
  fp32 m      4 B
  fp32 v      4 B
  fp16 梯度   2 B   （反向用它）
  ──────────────
  合计      16 B / 参数   （master + m + v = 12B 是大头）
```

用模型规模换算：

```text
7B 模型:  7e9 × 16 B ≈ 112 GB → 单卡 80GB 放不下
70B 模型: 70e9 × 16 B ≈ 1.12 TB → 必须分布式 + 状态切分
```

对比：SGD/Momentum 只要 8 B/参数（θ + g），所以小规模微调用 SGD 省一半显存；Adam 的"贵"主要贵在 m/v。

### 6. 省显存变体

| 方案 | 省什么 | 代价 |
|---|---|---|
| AdamW 8-bit（bitsandbytes） | m/v 量化到 8-bit，状态 8B→2B/参数 | 精度略降，训练曲线可能不稳 |
| Adafactor | 二阶矩做行/列因子分解近似 | 近似引入误差，长训练要验证 |
| Lion / Sophia | 换更新规则，省掉 v 或换用二阶信息 | 超参敏感，生态不统一 |
| FP8 训练（DeepSeek-V3 路线） | 权重/激活走 FP8，master 权重仍 BF16 | 工程复杂，优化器状态精度仍需保护 |

FP8 训练是目前训练侧的趋势：计算和通信降到 FP8，但**优化器状态和 master 权重通常保高精度**——"能压的是计算和通信，不能乱压的是状态"。

### 7. 和分布式训练的关系（ZeRO-1 / FSDP）

单卡放不下时，先切什么？ZeRO 的答案是从"最贵、最不需要每卡都有一份"的东西开始：

```text
ZeRO-1: 只切优化器状态（m/v）
  每步通信 ≈ 一次全量参数 all-gather + 一次梯度 reduce-scatter ≈ 2× 模型大小

ZeRO-2: + 梯度切分
  reduce-scatter 后每卡只保留自己的梯度片，再省一段

ZeRO-3: + 参数切分（= FSDP 的做法）
  参数也按层 gather，通信更多但显存最省
  PyTorch 的 FSDP 就是 ZeRO-3 的工程实现
```

训练一层的完整流程（ZeRO-1 视角）：

```text
forward  → backward（梯度 reduce-scatter，每卡拿到自己那片的梯度）
→ optimizer step（各卡只更新自己拥有的 m/v 片 + 对应参数片）
→ all-gather 全量参数 → 下一轮 forward
```

## 关键数据与取舍

| 优化器 | 每参数显存 | 特点 |
|---|---|---|
| SGD / Momentum | 8 B | 最省，收敛依赖 lr 调参 |
| Adam | 16 B | 稳定好用，训练默认 |
| AdamW | 16 B | 解耦 weight decay，主流 |
| AdamW 8-bit | ~10 B | 状态量化，省 6B/参数 |
| Adafactor | <16 B | 二阶矩近似，省 v |

取舍一句话：**AdamW 是质量与稳定性的默认选择，显存不够先切状态（ZeRO-1），再上 8-bit 状态，最后才动训练精度**。

## 与我何干

- **训练/并行 子类第一课**：接下来 ZeRO/FSDP、TP/PP/EP 通信都建立在"每参数 16B"和"状态可以切"这两件事上
- **[面试] 必考**：
  - "Adam 为什么比 SGD 好？" → 动量 + 自适应步长 + 偏差修正
  - "AdamW 和 Adam+L2 的区别？" → weight decay 是否被 v̂ 归一化，解耦后衰减更稳定
  - "7B 模型 AdamW 混合精度训练显存构成？" → fp16 参数 + fp32 master + m/v ≈ 16B/参数 ≈ 112GB，所以要 ZeRO/FSDP
  - "ZeRO-1 切什么、通信多少？" → 切优化器状态，每步 ~2× 模型大小通信
- **和推理线的区别**：推理只看权重 + KV cache；训练还要加 master weights + 优化器状态 + 激活，显存问题完全不同
- **算子线彩蛋**：optimizer step 本质是 elementwise kernel（m/v/θ 各自更新），以后可以写一个 Triton 版练手

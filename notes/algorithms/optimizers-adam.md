# 优化器：Adam / AdamW 与显存账

> 训练/并行类 · 从更新公式追踪到状态生命周期与分片

---

## 解决了什么问题

训练一个模型时，优化器把梯度历史变成参数更新。比较 SGD 与 Adam，关键不是给某个算法贴上“更稳”的标签，而是看更新规则、状态容量和通信路径：

1. **方向震荡**：只依赖当前梯度，梯度噪声大，路径来回摆动
2. **每参数同一步长**：不同参数尺度差异大（有的接近 0，有的很大），统一学习率顾此失彼
3. **状态容量**：Adam 为每个参数维护一阶和二阶统计，状态精度与分片方式直接决定显存。

Adam 使用动量和逐参数二阶统计调整更新；AdamW 将 weight decay 与梯度归一化解耦。分布式训练时，优化器状态、梯度和参数何时分片、何时临时聚合，是另一条必须沿时间线回答的路径。

## 核心思路

### 1. SGD 基线：为什么不够

```text
θ = θ - lr × g
```

- g 是当前梯度，lr 是学习率
- 问题：只看见"现在"，没看见"历史"；震荡时没有阻尼；每个参数都被同一个 lr 推

### 2. Adam：两个 EMA + 偏差修正

Adam 给每个参数维护两个指数滑动平均（EMA）：

```text
m = β1·m + (1-β1)·g          # 一阶矩：梯度的动量（方向感）
v = β2·v + (1-β2)·g²         # 二阶矩：梯度平方的 EMA（尺度感）

偏差修正（前几步 m/v 从 0 起步，会严重低估真实均值）：
m̂ = m / (1 - β1^t)
v̂ = v / (1 - β2^t)

更新：
θ = θ - lr × m̂ / (√v̂ + ε)
```

逐项理解：

| 项 | 作用 | 直觉 |
|---|---|---|
| m | 动量 | 梯度方向的历史平均，震荡互相抵消 |
| v | 自适应步长 | 梯度大的方向步子变小，梯度小的方向步子变大 |
| 偏差修正 | 前几步校准 | m/v 初始为 0，不修会偏小 |
| ε | 数值稳定 | 防止 √v̂ = 0 时除零 |

默认值：β1=0.9、β2=0.999、ε=1e-8。β2 接近 1 意味着 v 对历史非常保守；v 是未中心化的梯度平方的指数滑动平均（raw second moment），不是已经减去均值的统计方差。

### 3. 手算两步（验证理解）

设 β1=0.9、β2=0.999、lr=0.001，参数 θ 初始 1.0，梯度 g₁=0.1、g₂=-0.2：

```text
第 1 步 (t=1):
  m = 0.9×0 + 0.1×0.1 = 0.01
  v = 0.999×0 + 0.001×0.01 = 0.00001
  m̂ = 0.01 / (1-0.9) = 0.1
  v̂ = 0.00001 / (1-0.999) = 0.01
  θ = 1.0 - 0.001 × 0.1 / (√0.01 + 1e-8) ≈ 1.0 - 0.001 = 0.999

第 2 步 (t=2), g=-0.2:
  m = 0.9×0.01 + 0.1×(-0.2) = -0.011
  v = 0.999×0.00001 + 0.001×0.04 = 0.00004999
  m̂ = -0.011 / (1-0.81) ≈ -0.0579
  v̂ = 0.00004999 / (1-0.998001) ≈ 0.025
  θ = 0.999 - 0.001 × (-0.0579) / (√0.025 + ε) ≈ 0.999 + 0.000366 = 0.999366
```

要点：梯度从 +0.1 翻到 -0.2 时，一阶矩保留历史方向，二阶矩记录尺度，偏差修正负责消除零初始化造成的早期偏差。具体更新幅度仍由学习率、betas、epsilon 和梯度序列共同决定。

### 4. AdamW：解耦 weight decay

经典 Adam + L2 正则有个隐蔽问题：

```text
L2 正则：把 λθ 加进梯度 → g' = g + λθ
但 Adam 会用 v̂ 归一化 g' → weight decay 的实际强度被梯度尺度扭曲了
```

AdamW 的修法：**weight decay 不进入梯度，直接在更新后减**：

```text
θ = θ - lr × m̂/(√v̂ + ε) - lr × λ × θ
    └────── 梯度部分（Adam 原样）────┘   └─ 权重衰减（独立于梯度）─┘
```

- 效果：衰减项不进入一阶/二阶统计，更新含义更容易单独控制；是否采用仍由训练配方决定。
- 讨论 AdamW 与 Adam+L2 时，应写出两条更新式，并说明参数分组、学习率和 weight decay 是否对该参数生效。

### 5. 训练状态显存核算

每个参数的状态容量取决于实现约定。下面的 16 B/参数只对应一种 FP16/BF16 参数、FP16 梯度、FP32 master 与 FP32 m/v 的配置：

```text
全精度（fp32 训练）:
  参数 θ     4 B
  梯度 g     4 B
  动量 m     4 B
  二阶矩 v   4 B
  ──────────────
  合计      16 B / 参数

主流混合精度（fp16/bf16 训练）:
  fp16 参数   2 B   （前向/反向用它）
  fp32 master 4 B   （优化器只更新 master）
  fp32 m      4 B
  fp32 v      4 B
  fp16 梯度   2 B   （反向用它）
  ──────────────
  合计      16 B / 参数   （master + m + v = 12B 是大头）
```

用模型规模换算时，先把参数、梯度、master、m/v、激活和临时通信 buffer 分开相加，再考虑分片和重叠生命周期：

```text
7B 模型:  7e9 × 16 B ≈ 112 GB（仅上述模型状态，不含激活与临时 buffer）
70B 模型: 70e9 × 16 B ≈ 1.12 TB（实际放置取决于精度、分片和卸载）
```

对比：若参数和梯度均按 4 B 保存，SGD/Momentum 的状态项少于 Adam；具体字节数仍应按参数、梯度和 momentum 精度列式计算。Adam 的额外容量主要来自 m/v 及可能的 master copy。

### 6. 省显存变体

| 方案 | 省什么 | 代价 |
|---|---|---|
| AdamW 8-bit（bitsandbytes） | m/v 量化到 8-bit，状态 8B→2B/参数 | 精度略降，训练曲线可能不稳 |
| Adafactor | 二阶矩做行/列因子分解近似 | 近似引入误差，长训练要验证 |
| Lion / Sophia | 换更新规则，省掉 v 或换用二阶信息 | 超参敏感，生态不统一 |
| FP8 训练（具体 recipe） | 部分权重/激活/梯度走 FP8，master 与 optimizer state 通常保留更高精度 | 工程复杂，需核对 master/state dtype 与稳定性 |

FP8 训练的可行性取决于 recipe：计算和通信可以使用 FP8 表示，但 master 权重、m/v 和归约的精度必须按具体实现核对；“低精度计算”不等于“所有训练状态都低精度”。

### 7. 和分布式训练的关系（ZeRO-1 / FSDP）

单卡放不下时，先切什么？ZeRO 的答案是从“数据并行中每个 rank 都重复保存、但更新时只需一份”的状态开始：

```text
ZeRO-1: 只切优化器状态（m/v 及相关 optimizer state）
  参数和梯度仍复制；通信取决于梯度归约与参数同步实现

ZeRO-2: + 梯度切分
  reduce-scatter 后每卡只保留自己的梯度片

ZeRO-3: + 参数切分（FSDP 的 FULL_SHARD 路径）
  参数在前向/反向需要时 all-gather，完成后重新分片，显存更省但通信和调度更复杂
  PyTorch FSDP 提供相近的 full-shard 语义，但实现细节和配置仍需查版本文档
```

训练一层的状态流（以参数分片的 full-shard 语义为例）：

```text
前向前 all-gather 当前层参数 → forward → 按配置重新分片
→ 反向前再次 all-gather 当前层参数 → backward → reduce-scatter 梯度并释放临时副本
→ optimizer step 更新本地参数/状态分片 → 下一层或下一轮按配置再次 all-gather
```

## 关键数据与取舍

| 优化器 | 状态组成（需结合精度核算） | 特点 |
|---|---|---|
| SGD / Momentum | 参数、梯度及可选 momentum | 状态较少，收敛依赖学习率和动量配置 |
| Adam | 参数、梯度、m/v，可能还有 master copy | 自适应更新，状态容量较高 |
| AdamW | 与 Adam 类似的 m/v；额外解耦 weight decay | 更新规则不同，不自动减少状态 |
| AdamW 8-bit | 低精度状态与高精度参数/梯度的组合 | 需验证误差、溢出和实际峰值显存 |
| Adafactor | 分解或近似的二阶统计 | 以近似换状态容量，需按模型验证 |

取舍应按训练目标和资源约束展开：先列出状态精度与峰值生命周期，再选择状态分片、参数/梯度分片、卸载或低精度状态，并以收敛与 step time 验证。

## 与我何干

- **训练/并行子类第一课**：接下来 ZeRO/FSDP、TP/PP/EP 通信都建立在“状态组成可核算、并可按 rank 分片”这两个事实之上
- **和推理线的区别**：推理只看权重 + KV cache；训练还要加 master weights + 优化器状态 + 激活，显存问题完全不同
- **算子线彩蛋**：optimizer step 本质是 elementwise kernel（m/v/θ 各自更新），以后可以写一个 Triton 版练手

## 求职追问与示范回答

以下是教学示例，不代表个人实测：
- “Adam 为什么常用于 noisy/sparse gradient？”——说明一阶矩、未中心化二阶矩和偏差修正分别改变方向、尺度与早期估计；不要把 v 称为已经中心化的方差。
- “AdamW 和 Adam+L2 的区别？”——写出 weight decay 是否进入梯度，再说明它是否被 m/v 的归一化改变；解耦只改变更新规则，不自动减少状态。
- “混合精度训练显存如何核算？”——先列参数、梯度、master、m/v 的 dtype，再按峰值生命周期加入激活和临时 buffer，不能把 16B/参数当成普遍常数。
- “ZeRO-1 切什么、通信多少？”——切 optimizer state；通信量依梯度归约、参数同步和实现选择，需在同一 collective 定义下推导。

复述一条更新链时，先说明 $g_t$ 如何更新 $m_t,v_t$，再做偏差修正并计算梯度项；AdamW 另外执行 `-lr × weight_decay × θ`，因此 weight decay 不进入动量和二阶统计。若追问分布式，再说明当前层参数何时 all-gather、梯度何时 reduce-scatter，以及 optimizer step 在本地分片上完成。

## 官方资料核查

主 agent 已核对本地 CUDA Programming Guide 13.3：

- §5.4.11 WMMA：PDF 第623页（打印第607页），整个 warp 必须参与，fragment 元素映射 opaque，不能按 lane 假定内部布局。
- PDF 第624页（打印第608页）：`load_matrix_sync`/`store_matrix_sync` 的 mptr 需256-bit/32B对齐；half 的 leading dimension 为8的倍数、float 为4的倍数；mptr、ldm、layout 参数要求 warp 一致。
- PDF 第625页（打印第609页）：TF32 WMMA 需 `__float_to_tf32`，形状为 `16×16×8`，不能与 half 的 `16×16×16` 组合混写。
- PDF 第627页（打印第611页）：fragment 跨不同编译架构传递不具备安全 ABI 合同。
- §4.11.2 TMA：PDF 第363页（打印第347页），Compute Capability 9.0 及以后、1至5维 tensor map 与 async proxy 语义。

课程正文给出了可点击本地 PDF 页链接，在线资料只作为对应主题入口：官方 Triton [03-matrix-multiplication](https://triton-lang.org/main/getting-started/tutorials/03-matrix-multiplication.html)、[`tl.dot` API](https://triton-lang.org/main/python-api/generated/triton.language.dot.html)、[cuBLAS 文档](https://docs.nvidia.com/cuda/cublas/index.html)和 [CUTLASS Efficient GEMM](https://docs.nvidia.com/cutlass/latest/media/docs/cpp/efficient_gemm.html)。cuBLAS 在线版本按13.4表述，未与本地13.3混称；Triton `tl.dot` 的 `tf32/tf32x3/ieee` 选项和 FP32 输入精度边界已按当前 API 说明处理。

## 语义与资源审查结论

正文统一以用户已有 Triton/naive CUDA 的 `A[M,N]B[N,K]=C[M,K]` 为主符号，明确官方 `A[M,K]B[K,N]=C[M,N]` 的 N/K 映射；旧 `tiled_fp16.cu` 单独保留 `A[M,K]B[K,N]=C[M,N]`，说明 `x→m,y→n`、`tileLen=32`、1024 threads 和旧 leading dimension 地址步长。

正文直接嵌入并通过构建检查原始 `solutions/cuda/gemm/naive_float.cu` kernel 与 `solutions/triton/matmul.py` kernel；未改写或覆盖旧源。WMMA 示意使用 row-major B，并注明指针是 tile 起点；不把 fragment lane 映射写成可移植事实。

CPU 检查脚本只使用 Python 标准库，固定断言：

- 教学地址例子 `M=3,N=2,K=5` 的 A/B/C 偏移 `[2,3]`、`[2,7]`、`7`；
- `M=65,N=33,K=67`、`BM=64,BN=32,BK=64` 的 `grid=(2,2)`、2次归约轮、store 每坐标恰好一次，A/B mask 覆盖完整逻辑集合；
- 总 FLOPs `2×65×33×67=287430`，tile FLOPs `262144`，FP32 tile 输入字节 `16384`，input-only reuse AI `16`；`BN=64` 保持该 AI 但归约轮变为1；
- `BM=128,BK=256,FP32` 的 input-only AI `42.666667`、逻辑 accumulator 字节 `131072`；
- CPU FP32 数值模型中的不同归约顺序差异。

Roofline 账本区分三种范围：完整输入只读一次加 C 写回的 AI `945.230769 FLOP/B`；按 `BM=128,BN=32,BK=256`、每 CTA 每轮重新读 A/B 且不计 cache 的 AI `42.08219 FLOP/B`；单轮 input-only tile AI `42.666667 FLOP/B`。正文明确真实 DRAM/L2 流量要由 counter 测量。

`S×s×BN×(BM+BK)` 中的 S 被定义为“同时驻留完整输入 tile 的缓冲份数”，不等于无条件的 `num_stages`。对 `BM=128,BN=32,BK=256,FP32`，一份 A/B tile 为 `49152B`；机械套 `S=3` 会得到 `147456B`，却与 s3 可运行及 Nsys 约 `0.098MB` metadata 不一致。因此实际 buffer 数归因于编译器流水化、复用和布局；acc `131072B` 也不计入 shared 需求。

## 实测证据边界

2026-08-26 RTX 3090 IEEE FP32 sweep 使用同次 `torch.mm=17.138ms / 24058.3 GFLOPS`，保留五个候选结果：24.924、22.298、28.354、编译失败、22.033ms。`BK=64→128` 的比较固定 `BM=128,BN=32,w4,s3`，因此归约循环均为192；`BK=256,w8` 同时改变 BK 与 warp 数，不能把其最快结果归因于单一旋钮。资源失败 `Required shared=131072B / Limit=101376B` 按单 block 启动资源记录，不解释为 SM 总量。

2026-08-30 Nsys 两份 raw trace 以首列非空白字段匹配可能带省略号的 Start，第二列完整读取 Duration，再筛选 `Grid=64×16×1`、`Block=256×1×1`；两份各得到60次大 shape 调用，排除了4次 correctness。s3/s2 Triton mean 分别为 `21.208284350ms`、`22.361580216667ms`，median 分别为 `21.163139`、`22.317032ms`，Reg/Trd 均255，DymSMem 约0.098/0.049MB。s2 慢约5.4379%；“缓冲减少导致延迟隐藏变化”只保留为推测，无 NCU hardware counters 时不写成具体 stall/L2/DRAM/achieved occupancy 因果。CUTLASS 同次 mean 为16.716166717/16.682412133ms，单独保留。

PATH 收口摘要中的 RTX 3090 `20.830ms / 19794.1 GFLOPS / 80.3%` 没有同次完整 raw 对照，单独标注为既有记录；平台归档的 A100-80GB `24.54ms` 同样不与服务器表混合。

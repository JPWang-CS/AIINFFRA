# CUDA 执行模型讨论记录（2026-10-09）

本记录整理围绕第二章执行模型的问答。下列用户问题均为概括，不是逐字引用；技术解释由 Agent 整理。课程正文已吸收适合连续阅读的解释。这里的概念讨论不代表 CUDA kernel 已编译或在 GPU 上验证。

## 已讨论并确认

### 分支、谓词与两边都计算

**用户问题（概括）：**一个 warp 的 lane 分别进入 even/odd 分支时，是否等于整个 warp 执行两次？如果两边代码都要发指令，那是不是还是执行两次？用谓词或先计算两个候选再选择，是否真的更快？

**Agent 整理：**显式分歧分支会让 warp 分别处理两条指令路径，每条路径只让相应活动 lane 参与；不是每个线程都把两个分支的函数各算一遍。谓词执行可以减少跳转控制，但两条路径的指令仍可能都需要调度。若源码先计算两个候选值再选择，每个线程确实可能执行两份算术；编译器也可能改写纯算术，因此要查看生成代码。短小工作可能值得用谓词省跳转，长工作若整 warp 选择一致，则真实分支可能跳过另一条路径；应结合指令数量、活动 lane 和分支一致性判断。

### 独立线程调度与等待

**用户问题（概括）：**Volta 起的独立线程调度如何理解？Ascend 的 AIV/AIC 和 GPU SM 的差别是否是后者能在一个任务等待时继续做别的工作？

**Agent 整理：**warp 中某些线程等待时，其余线程的执行位置可以不同；硬件仍按活动线程组织 warp 指令。若一个 warp 因普通数据依赖暂时不能发射，SM 可以选择另一个已驻留且就绪的 warp，不必等当前 block 结束。Ascend C 的核实例任务划分与 SM 的 warp 发射属于不同抽象层，不能从这一点推出 AIV/AIC 等待时不能调度其他任务。正文保留这一层次边界，具体行为仍要按设备架构和编程模型分析。

### Shuffle 的来源 lane、多个值与寄存器

**用户问题（概括）：**`__shfl_sync(mask, value, 0)` 是否只由 lane 0 提供值？若需要两个线程的值怎么办？`value` 为什么说是寄存器？

**Agent 整理：**每个参与线程都传入自己的 `value`；参数 `0` 指定结果从 lane 0 取得。需要 lane 0 与 lane 1 的值时，所有参与线程分别执行两次 shuffle，来源参数为 0 和 1。普通局部标量通常由寄存器承载，因此 shuffle 的操作数是每线程的寄存器值；若发生寄存器溢出，编译器会先取回操作数。有效来源 lane 必须参与调用并持有已定义的值，mask 也必须符合实际参与线程。

### 尾块与负载均衡

**用户问题（概括）：**除增大每轮处理量使其整除、或均分尾部数据外，还有哪些负载均衡办法？

**Agent 整理：**可以合并独立小任务、对耗时不均的可拆任务使用动态领取、调整 tile/block 工作量与资源占用，或为边界形状采用专用 kernel。动态调度不能消除等时不可拆任务的尾部下界：17 个等时 block 分到 8 个执行位置，至少有一处处理 3 个 block；补 7 个空 block 凑 24 个不会减少计算。CUDA 会在 block 释放资源后继续安排后续 block，不能把“波”误解为全设备的硬同步屏障。

### `fmaf` 与输入、计算、累加、输出类型

**用户问题（概括）：**`fmaf` 的官方文档入口在哪里？低精度输入为什么还会在代码中转换？输入转 FP32 后是否就按 FP32 乘法？输出类型能说明累加类型或 Tensor Core 路径吗？

**Agent 整理：**官方入口为 [`fmaf` CUDA Math API](https://docs.nvidia.com/cuda/cuda-math-api/cuda_math_api/group__CUDA__MATH__SINGLE.html#_CPPv44fmaffff)。FP16 输入可转换为 FP32，再用普通 FP32 FMA 累加；转换只保留 FP16 已存下的数值，不会还原舍入前丢失的信息。Tensor Core MMA 是另一条矩阵计算路径，需看操作数类型、指令与累加器定义。输入存储类型、乘法路径、累加器类型和写回类型应分别从代码/API/生成指令确认，不能仅凭输出 dtype 推断其余三者。

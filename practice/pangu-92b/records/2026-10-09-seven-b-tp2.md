# openPangu 7B 双机 TP2 实操记录

2026-10-09，openPangu-Embedded-7B-V1.1 在 11 号机与 4 号机完成双节点推理。每台使用一张物理 5 号卡，11 为 API 与 rank 0，4 为 headless worker 与 rank 1。采用个人 CANN 9.2.0、vLLM 0.14.0 与 Omni-NPU，BF16、TP2、eager、1024 上下文。

两侧实际日志均记录 world size 2、backend hccl 与同一跨机 rendezvous 地址，分别加载约 7.51 GiB 模型权重。模型和框架启动前重新检查 SHA256；两侧 NPU worker 实际加载个人 ACL/HCCL/HCOMM 与 Torch-NPU 库。

验证结果：

| 请求 | 输入/生成 token | 输出 | 完成 |
|---|---|---|---|
| 自我介绍 | 22/35 | 完整介绍，模型名称“盘古” | stop |
| 17+25 非流式 | 26/4 | 42 | stop |
| 17+25 流式 | 26/4 | 42，完整 SSE | stop + [DONE] |
| stop=["42"] | 26/3 | 文本截去 42 | stop_reason="42" |

四组请求均 HTTP 200，每个输入只有一个 BOS。普通与流式算术 token 序列一致。API 请求 ID 与引擎随机后缀 ID 的映射、输入输出、SSE 与两侧日志完整保留。

启动修正包括插件模型参数与私有 TMPDIR。Omni-NPU 会直接读取 sys.argv 中的 --model 参数，因此在导入插件前完成设置。ZMQ 使用基础路径加 UUID，运行目录较长时超过 Unix socket 的 107 字节限制；采用个人部署目录内的短路径，每次运行独立创建。通信前置阶段通过 TLS 与空闲卡只读盘点选择物理 5，没有修改设备 TLS。

两台服务均退出 0，本轮进程组为空，物理 5 恢复空闲，选定端口释放，公共文件哈希未变化。所有远端写入位于个人部署目录，shell 历史关闭并清空当前会话历史。
